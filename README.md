# 局域网唤醒（Wake-on-LAN）Android App

一个**只做一件事**的 Android 应用：点一下设备卡片，按你填写的参数把标准的 Wake-on-LAN 魔术包发出去。
为**红米 / Redmi（HyperOS、MIUI）**机型适配，安装包约 114 KB，基础唤醒功能**不申请任何运行时权限**。

> 设计取舍：**不做任何在线检测**。检测（ping / 读 ARP 表）限制多、误判多，而且跟"能不能唤醒"毫无关系 ——
> 唤醒只需要一个格式正确的魔术包。MAC、IP、端口是否正确由使用者自己核对；应用只负责把包发对、发出去。

---

## 1. 功能

| 功能 | 说明 |
| --- | --- |
| 设备列表 | 保存多台电脑的名称、网卡 MAC、IP、端口、备注，支持编辑 / 删除 / 复制 MAC |
| 一键唤醒 | 点击设备卡片**立即发出一个魔术包**（102 字节标准格式），没有任何检测与前置判断 |
| 发送目标 | 填了 IPv4 → 单播给它；没填 → 直接发广播。内核 ARP 解析不到时会自动改用广播（见下） |
| 强制走 Wi-Fi | 用 `Network.bindSocket()` 把发送套接字绑定到 Wi-Fi，即使「Wi-Fi 无互联网 + 手机开着流量」也不会发错网卡 |
| 状态面板 | 顶部显示当前 Wi-Fi 网卡、本机 IP/掩码、自动算出的广播地址（仅用于确认手机在不在正确的网段） |
| 设置 | 默认唤醒端口、每个目标发送次数、是否同时向端口 7 发送 |
| **飞书远程唤醒** | 可选功能：在飞书里给机器人发 `/wake 设备名`，本机收到后发唤醒包并回复结果 —— 详见[第 10 节](#10-飞书远程唤醒可选) |

**设备表单只需要填 4 项**：名称、MAC，以及可选的 IPv4 与备注。

### 发送逻辑：先单播，发不出去才广播

唤醒只需要**一个包**，所以点击卡片不做任何检测、也不重复发（除非你把「发送次数」调大）。但"发给谁"有个坑：

- 单播到 `192.168.0.3` 需要手机内核先用 **ARP** 问出它的 MAC。电脑关机时若网卡不回 ARP，
  这个包会被内核**直接丢掉**（而 `send()` 仍然返回成功，程序会误以为发出去了）。
- 广播（`192.168.0.255`，二层目的地址 `ff:ff:ff:ff:ff:ff`）**不需要 ARP**：网段里每台设备都会收到，
  关机的那台网卡照样能按载荷匹配到魔术串 —— 这是唯一能保证"包真的出去了"的方式。

所以流程是：**先发单播 → 查一次本机邻居表 → 解析成功就结束；解析不到就改发一个广播**，并提示：

```
已发送 1 个魔术包 → 192.168.0.3 :9
```

或（发生回退时）：

```
已发送 1 个魔术包 → 192.168.0.255 :9
192.168.0.3 解析不到 ARP，单播包发不出去，已改用广播 192.168.0.255
```

> 这段不是"检测电脑在不在"，而是**确认自己这一发包有没有真的离开手机** —— 它保证你点一下就有包出去。
> 邻居表读取本身也有两条路（`ip neigh show <ip>` → `/proc/net/arp`），都读不到时照样会广播，唤醒不受影响。
>
> 另外：`192.168.0.255` 与 `255.255.255.255` 在二层是同一个广播帧，而 WOL 网卡只看载荷、
> 不看 IP 目标地址，所以只发一个即可。

## 3. 构建 APK

本项目**不依赖 Gradle / Android Studio / AndroidX**，用 `aapt2 + javac + d8 + zipalign + apksigner`
串成一条最小编译流水线，首次运行会自动从国内镜像下载所需构件（约 250MB，缓存在 `.toolchain/`）。

```powershell
# 在仓库根目录执行
powershell -ExecutionPolicy Bypass -File tools\build.ps1
```

产物：`dist\WolWake-1.0.0.apk`

其他命令：

```powershell
# 只下载/校验工具链
powershell -ExecutionPolicy Bypass -File tools\toolchain.ps1

# 运行纯逻辑单元测试（MAC 解析、102 字节魔术包、子网广播、指令解析、回复文案）
powershell -ExecutionPolicy Bypass -File tools\test-packet.ps1

# 指定版本号构建
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -VersionName 1.1.0 -VersionCode 2
```

**前置条件**：Windows + PowerShell 5.1+。
本机已有完整 JDK 17 时会直接复用（必须含 `jdk.zipfs` 模块）；否则从清华 TUNA 镜像下载 OpenJDK 17。
Android 构件来自腾讯云 `mirrors.cloud.tencent.com/AndroidSDK/`，失败时回退 `dl.google.com`。

**关于签名证书**：`keys/wol-release.jks` **不入库**（`.gitignore` 里排除）。首次构建时 `build.ps1` 会用
`keytool` 自动生成一个自签名证书并复用它签名，所以克隆仓库后可直接构建。注意两点：

- **换一台机器构建出的证书不同**，签名不一致的 APK **无法覆盖安装**到已有安装上（需先卸载）；
  想保持一致，就把原来那台的 `keys/wol-release.jks` 拷过来。
- 该证书仅用于自用侧载，**不是上架密钥**（应用商店要求的是另一套正式签名流程）。

## 4. 安装到红米手机

1. 把 `dist\WolWake-1.0.0.apk` 传到手机（微信文件传输 / 数据线 / 局域网 HTTP 均可）。
2. 用「文件管理」点击 APK 安装。
3. 若被拦截：
   - **关闭「纯净模式」**：设置 → 应用设置 → 应用管理 → 右上角设置图标 → 纯净模式 → 关闭；
   - 允许安装未知来源应用：设置 → 应用设置 → 权限管理 → 安装未知应用 → 允许「文件管理」；
   - 弹「安全检测 / 应用宝扫描」时选「继续安装」。
4. 首次启动后确认联网权限：设置 → 应用设置 → 应用管理 → 局域网唤醒 → 权限 → 若有「联网/网络访问」项需允许。

> 基础唤醒功能只需要 3 个「安装期普通权限」（INTERNET / ACCESS_NETWORK_STATE / ACCESS_WIFI_STATE），
> 不需要定位、存储、后台运行等敏感权限，装好后直接可用、不弹授权框。
> 只有当你启用**飞书远程唤醒**时，才会额外申请「通知」权限（用于常驻通知）以及选择是否放开省电限制。

## 5. 使用说明

1. **添加设备**：右上角 `+`，填名称与 MAC；建议填 IPv4（会走单播，更精准）。
   - Windows 上查 MAC：`cmd` 里执行 `ipconfig /all`，看对应网卡的「物理地址」；
   - 想在电脑关机时也能唤醒，**建议留空 IP 用广播**（广播不依赖 ARP）；
   - 想固定 IP 的话，建议在路由器上做 DHCP 静态绑定（MAC↔IP）。
2. **唤醒**：点击设备卡片 → 立即发一个魔术包，提示「已发送 1 个魔术包 → …」。
3. **长按卡片**菜单：**编辑** / 复制 MAC / 删除。
4. **右上角「设置」**：
   - 默认唤醒端口（默认 9，老网卡也可能用 7）；
   - 每个目标发送次数（默认 1；偶尔唤醒不成功可调到 3~5，对抗 Wi-Fi 广播丢包）；
   - 同时向端口 7 发送（勾选后每个目标会向 9 和 7 各发一次）。

## 6. 目标电脑需要满足的条件（关键）

Wake-on-LAN 必须**在电脑端提前配置好**，否则手机发再多包也叫不醒：

1. **有线网卡**：绝大多数无线网卡不支持 WOL，请用主板/网卡的有线口，且关机后网口指示灯仍亮。
2. **BIOS/UEFI**：开启 `Wake on LAN` / `Power On By PCI-E` / `Resume By LAN`（不同主板叫法不同）。
3. **Windows 网卡属性**（设备管理器 → 网络适配器 → 属性）：
   - 「电源管理」页：勾选「允许此设备唤醒计算机」与「只允许幻数据包唤醒计算机」；
   - 「高级」页：`Wake on Magic Packet` 设为 Enabled；`节能以太网 / Energy Efficient Ethernet`、
     `绿色以太网` 建议关闭；`关机网络唤醒（Shutdown Wake-On-Lan）` 设为 Enabled。
4. **关闭 Windows 快速启动**：控制面板 → 电源选项 → 选择电源按钮的功能 → 更改当前不可用的设置 →
   取消勾选「启用快速启动」。**快速启动是 S5 唤醒失败最常见的原因**。
5. 电脑与手机在**同一网段**（本应用基于二层广播，跨网段需要路由器配置转发，不在本版本范围内）。

## 7. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 顶部提示「未连接 Wi-Fi」 | 手机没连 Wi-Fi 或处于飞行模式；连上后状态面板会显示网卡与广播地址 |
| 提示「已自动改用广播」 | 填的 IP 解析不到 ARP（电脑关机且网卡不回 ARP），属正常回退；**留空 IP 直接走广播即可不再出现该提示** |
| 发送失败：没有任何数据包发送成功 | 手机不在内网 Wi-Fi，或 Wi-Fi 完全没有 IPv4 地址 |
| 提示已发送，但电脑没醒 | 广播包不依赖 ARP，正常情况下包一定已经离开手机 → 先查第 6 节的 BIOS / 网卡 / 快速启动；**多台电脑都叫不醒**才怀疑网段或 AP 隔离 |
| 电脑 IP 和手机不在同一网段 | 看顶部状态面板的**广播地址**（如 `192.168.0.255`）必须和电脑 IP 同网段（`192.168.0.x`）。很多路由器把 2.4G/5G 或访客网络分成不同网段，此时广播到不了 —— 换到同一 SSID 即可 |
| 某些路由器下广播无效 | 路由器/AP 丢弃广播时，填好 IP 走单播（前提是网卡支持 ARP Offload 或缓存未过期） |
| 手机连的是 5G 移动数据 + Wi-Fi | 已处理：唤醒包强制从 Wi-Fi 出口发出（绑定 `Network`） |
| 覆盖安装失败 | 用的是 `keys/wol-release.jks` 固定签名，保留该文件即可覆盖升级 |
| 想抓崩溃日志 | 手机开发者选项打开 USB 调试后，电脑执行 `adb logcat -b crash`；不方便连电脑时，可用拨号盘输入 `*#*#284#*#*` 生成 bugreport，里面包含崩溃堆栈 |

### 构建期的两道自动防线

`tools\build.ps1` 会在编译前自动做两项检查，避免「APK 能构建但装不上/一用就崩」：

1. `check-layouts.ps1`：扫描全部布局，任何视图（含其引用的 style）缺少 `layout_width` / `layout_height` 立即中止构建。
2. `resources.arsc` 必须为 STORED 且 4 字节对齐 —— 否则 Android 11+ 直接拒绝安装，构建末尾会自检并报错。

## 8. 实现要点（便于二次开发）

- **魔术包**：`6 × 0xFF + 16 × MAC = 102 字节`（`WolPacket`，含单元测试）。
- **广播地址**：从 `ConnectivityManager.getLinkProperties()` 取本机 IPv4 与前缀长度，按 `ip | ~mask` 通用计算，
  /16、/23、/25 都正确（`NetMath.broadcastAddress`）。
- **发送**（`WolSender.send`）：`DatagramSocket`（未绑定创建）+ `setBroadcast(true)` +
  `Network.bindSocket(socket)` 绑定 Wi-Fi 出口，`repeat` 次（默认 1）、间隔 120ms。目标选择：
  1. 填了 IPv4 → 先发单播给它；
  2. 等 150ms 后查本机邻居表（`ip neigh show <ip>`，失败回退 `/proc/net/arp`）确认该单播包真的发出去了；
  3. 解析不到 → 该单播包已被内核丢弃，改发一个广播包（设备的旧 `broadcast` 覆盖值 → 本机网段广播 →
     `255.255.255.255`），并在结果里带上 `fallbackFrom` / `fallbackTo` 供界面提示。
- **没有任何检测代码**：应用不会 ping、不会扫描网段、不会上报数据；只在你点卡片时发送一个魔术包。
- **飞书远程唤醒**（可选功能，见第 10 节）：`FeishuPollService`（前台服务）每 N 秒调一次
  `GET /open-apis/im/v1/messages` 拉取机器人单聊里的新消息 → `FeishuCommand` 解析 → 复用 `WolSender` 发包 →
  `POST /open-apis/im/v1/messages` 回复结果。单聊的 `chat_id` 通过「给用户 open_id 发消息，从响应里取回
  `data.chat_id`」自动获得。轮询带**持久化时间游标 + message_id 去重 + 10 分钟追赶上限**，所以重启不会重放历史指令。
- **持久化**：`SharedPreferences` + `org.json`（Android 框架自带），无第三方依赖。

## 9. 已知限制

- **不做在线状态显示**：这是刻意的设计取舍 —— 唤醒只需要一个魔术包，状态检测既不可靠也不必要。
  如果你想知道电脑是否已开机，用「远程桌面 / 路由器后台」等更直接的方式。
- 定时唤醒、快捷磁贴、桌面小组件、导入导出、批量唤醒**未实现**；磁贴与小组件属于纯系统 API，
  定时唤醒在 HyperOS 上需要「自启动 + 无限制省电」且仍可能被系统限制。
- 跨网段 / 跨 VLAN 唤醒需要路由器支持定向广播转发（或改用中继），不在本版本范围。
- 发送次数默认为 1；若目标机网卡对丢包敏感，可在设置里调到 3~5。
- **飞书远程唤醒**：轮询有秒级延迟（默认 10 秒，可调到 5 秒）；依赖手机后台常驻（HyperOS 需省电白名单）；
  `App Secret` 以明文存在手机本地。

## 10. 飞书远程唤醒（可选）

**一句话**：家里常驻一台连 Wi-Fi 的手机跑这个 App；你在任何地方用飞书给机器人发 `/wake 书房台式机`，
手机收到后发出唤醒包，并在飞书里回复结果。

### 10.1 为什么是「轮询」而不是「事件推送」

飞书在公网、你家没有公网 IP，而飞书的「事件订阅 / 长连接」只有官方 SDK（Go/Java/Python/Node）支持，
Android 端自己实现它的 WebSocket 协议风险太大。所以改用**主动轮询**：手机每 10 秒调一次
`GET /open-apis/im/v1/messages` 拉取机器人单聊的新消息。该接口限频 **1000 次/分钟**，我们只有 6 次/分钟，
毫无压力；代价是**秒级延迟**而不是「瞬间响应」。

### 10.2 前提

- 一台**常驻家里、插电、常连家里 Wi-Fi** 的安卓设备（旧手机/平板）—— 它才是真正发出唤醒包的那台设备，
  所以必须与目标电脑在同一网段。
- 你能在飞书开放平台创建并发布「企业自建应用」（管理员）。

### 10.3 飞书侧配置（三步）

1. 打开 https://open.feishu.cn/app → **创建企业自建应用**，记下 `App ID` 与 `App Secret`。
2. **添加应用能力 → 机器人**；**权限管理**开通三项：
   - `im:message:readonly`（读取单聊消息）
   - `im:message:send_as_bot`（以应用身份发消息）
   - `contact:user.id:readonly`（用手机号换 open_id，仅首次使用）
   > 单聊方案**不需要** `im:message.group_msg`（那是「群聊读全部消息」才要的），也**不需要建群**，
   > 更不需要加任何好友。
3. **应用发布 → 创建版本 → 发布**；可用范围**只勾你自己**；然后在飞书工作台里启用一次该应用。
   > 权限与机器人能力都必须**发布之后**才生效。

### 10.4 App 侧配置

App 右上角「设置」→「飞书远程唤醒…」：

1. 填 `App ID`、`App Secret`、你自己的手机号；
2. 点 **连接并获取会话** —— App 自动完成：取凭证 → 手机号换 `open_id` → 机器人主动给你发一条
   「🔗 飞书远程唤醒已连接」→ 从响应里取回单聊 `chat_id` 保存，并把 `open_id` 自动填进白名单；
3. 之后在飞书里打开与机器人的单聊（就在刚收到的那条消息里），直接发指令即可；
4. 「发送测试消息」随时验证回复链路；「后台常驻设置说明」里有 HyperOS 的省电设置步骤。

### 10.5 指令

| 指令 | 说明 |
| --- | --- |
| `/wake 书房台式机` | 发唤醒包并回复执行结果（也可写 `/唤醒`，或用序号 `/wake 1`） |
| `/list` 或 `/设备` | 列出设备与序号 |
| `/help` | 指令帮助 |
| 其它文本 | 静默忽略（不回复） |

回复示例：

```
✅ 已发送 1 个魔术包 → 书房台式机（AA:BB:CC:DD:EE:FF）
目标 192.168.0.3 :9
来源 192.168.0.23/24
```

若手机不在内网，会回 `⚠️ 唤醒失败：未连接 Wi-Fi，无法发送唤醒包`。

### 10.6 后台常驻（HyperOS 必做）

息屏后仍要按间隔轮询，必须让系统不清理这个服务：

1. 设置 → 应用设置 → 应用管理 → 局域网唤醒 → **省电策略 → 无限制**；
2. 允许**自启动**；
3. 最近任务里**下拉锁定**本应用；
4. 通知栏会常驻一条「飞书远程唤醒」通知（文案是 `待命中 · 每 N 秒检查一次指令`），可据此判断服务是否还活着。
   这条通知**不能关**：前台服务在 Android 8+ 上必须显示通知，否则系统会判定应用异常并杀掉服务。
   为了不打扰，它被设为**低级别**（有图标但不出声、不弹横幅），并且**只在状态变化时才更新文案**
   （启动 / 唤醒成功 / 出错），不会每轮轮询都刷新。

验证方法：锁屏 30 分钟后从飞书发一条指令，应在 10~60 秒内收到回复。

### 10.7 排错

程序把错误分成两类，只有**需要你动手**的那类才会推到飞书会话里：

| 类别 | 例子 | 行为 |
| --- | --- | --- |
| **需要处理** | `99991672` 权限未开通、`99991664` Secret 变了、`232034` 应用未启用、`230013` 不在可用范围 | 在会话里提醒一次（同一故障不重复刷屏），改好后自动恢复正常 |
| **临时故障** | `请求失败：timeout`（网络超时）、`code=2200 Internal Error`（飞书服务端偶发） | **只在 App 内和通知里显示，不打扰你**；程序自己重试，恢复后静默继续 |

> 所以如果你在会话里看到 `timeout` / `code=2200` 之类的提示刷屏，那是**旧版本**的行为；
> 新版本遇到这类临时故障不会发消息。若手机连续 15 分钟连不上飞书，才会提醒一次「手机连不上飞书」。

| 现象 | 处理 |
| --- | --- |
| 提示 `code=232034` | 应用未在租户内启用：去飞书工作台启用一次 |
| 提示 `code=230013` | 你不在应用可用范围内：应用发布 → 可用范围 → 加上你自己 → 重新发布 |
| 提示 `code=230006` | 未添加「机器人」能力，或添加后没重新发布版本 |
| 提示 `code=230027` / `code=99991672` | 权限未开通，或开通后没重新发布版本 |
| 提示 `code=230053` | 你在飞书里关闭了该机器人的消息，重新允许即可 |
| 提示 `code=99991664` / `code=99991663` | App Secret 被重置了：复制当前 Secret 填回 App 保存 |
| 指令发出后很久没反应 | 手机不在内网/没网，或服务被系统清理：看常驻通知是否还在；按 10.6 配置白名单 |
| 回复「未连接 Wi-Fi」 | 手机当前不在家里内网 Wi-Fi 上（这是设计使然：唤醒包必须从内网发出） |
| 换手机 | 新设备上重新「连接并获取会话」即可；`chat_id` 不变（同一应用 + 同一用户） |

### 10.8 安全

- **飞书可用范围只勾你自己** → 原则上只有你能给机器人发消息；
- App 内还有 `open_id` **白名单**再挡一道，非白名单消息**静默忽略**（不回复、不动作）；
- `App Secret` 明文存在手机本地：建议只申请上面三项最小权限、可用范围仅自己；不再需要时在飞书侧重置 Secret；
- 应用只与飞书官方域名 `open.feishu.cn` 通信，不会把凭证发往其它地方。
